# 最终演示数据库初始化数据清单

本文记录执行以下命令后，各模块写入 `database/vCampus.accdb` 的初始数据：

```powershell
java -jar vcampus-server\target\vcampus-server-0.1.0-SNAPSHOT.jar --rebuild-demo-database
```

清单以 2026-09-11 的初始化代码和重建后数据库为准。正常启动服务器不会清空数据库；只有显式执行上述重建命令才会备份旧库并重新生成演示数据。

## 7. 操作审计

- 用户审计表初始化 1 条 `DEMO_DATABASE_INITIALIZED` 记录，表示演示库重建并通过校验。
- 初始选课管理审计为 0 条。
- 后续新增或修改账号、重置密码、教师资格变化、选课管理等操作会继续写入相应审计表。
- 历史记录中的姓名是办理时快照；当前姓名始终由 `tblUser.displayName` 提供。

## 8. 当前已发现的数据一致性注意项

下面两项是对 2026-09-11 实际重建库的直接检查结果，应在最终演示前清理：

1. 医院普通启动种子仍会补回 2 条属于旧医生 `doctor-sun` 的排班，但最终 10 名医生中已经没有该医生，因此形成 2 条孤立排班。
2. 当前 14 条医院预约及账单使用旧的合成患者 `userId`，不属于最终 39 个账号；2 份患者档案中也有 1 份属于旧合成患者。

除上述已明确列出的医院旧演示记录外，重建器已校验账号、一卡通号、学生、教师、医生、任课关系、选课、借阅、预约、购物车和订单等主要跨表引用不存在孤立记录。

## 9. 维护原则

- 本文件描述“显式重建后的初始状态”，不记录演示过程中后来新增的数据。
- 修改初始化代码、人员清单或演示数量时，必须同步更新本文件和 `database/README.md`。
- Git 只提交初始化代码和本文档，不提交运行中的 `vCampus.accdb` 或备份文件。
