# 数据表归属与协作边界

本表先确定“谁能修改哪类数据”，具体字段由模块负责人在各自数据字典中提出并经评审确认。

| 模块 | 数据字典 | 本模块拥有的数据 | 允许引用的外部标识 |
|---|---|---|---|
| 用户管理 | `user.md` | 账号、角色、权限、会话 | 无 |
| 学生学籍 | `student.md` | 学生、院系、专业、班级 | `userId` |
| 选课系统 | `course.md` | 课程、开课、选课、成绩 | `userId`、`studentId` |
| 图书馆 | `library.md` | 图书、馆藏、借阅记录 | `userId`、`studentId` |
| 商店 | `shop.md` | 商品、库存、购物车、订单 | `userId` |
| 医院 | `hospital.md` | 科室、医生、排班、预约 | `userId`、`studentId` |

规则：

- 表名使用 `tbl<PascalCase>`，字段使用 `lowerCamelCase`。
- 模块负责人只能通过本模块 DAO 更新本模块拥有的表。
- 跨模块只保存稳定 ID，读取外部信息走已评审的服务/action，不复制密码、姓名等数据。
- 二进制 `vCampus.accdb` 由数据库集成人统一生成；日常 PR 只提交数据字典、建表脚本和虚构种子数据。
- Access/JDBC 最小连接实验通过前，六模块可以完成用例、UI、DTO/action、服务接口和数据字典，但不要自行引入其他数据库。
