# 共同阅读与首次行动

## 1. 每位成员必须共同阅读

按顺序完成，阅读后在团队启动 Issue 中勾选姓名：

1. `docs/课程原始材料/软件实践安排(202509).docx`
   - 重点：课程项目、考核说明、组织形式、提交材料、开发约束、答辩流程。
2. `docs/课程原始材料/软件设计说明书DEMO(20250825).docx`
   - 重点：系统结构、模块设计、公共模块、网络、多线程、数据库设计的写法。
3. `docs/01-需求基线.md`
4. `docs/02-六人分工.md`
5. `docs/03-总体架构与接口约定.md`
6. `docs/04-四周交付计划.md`
7. `docs/05-GitHub协作规范.md`
8. `docs/06-验收与提交清单.md`
9. `docs/07-会议与进度记录.md`
10. `docs/08-开发环境统一规范.md`

## 2. 第一次团队会议必须作出的决定

- 填写 6 人姓名、学号、GitHub 用户名和联系方式。
- 确认模块负责人；如需互换，只交换模块，不删减模块。
- 明确教师最终允许的数据库版本和机房运行环境。
- 确认每周上机日期，把相对里程碑改成实际日期。
- 在 GitHub 建立 6 个模块 Epic Issue 和公共任务 Issue。
- 由全员共同通过需求基线和第一版接口契约。

## 3. 首次开发前的完成定义

只有以下事项全部完成，才开始多人并行写业务代码：

- Maven 多模块骨架能在 JDK 8 下构建。
- 6 人运行 `scripts/check-environment.ps1` 均通过，并把结果记录在启动 Issue。
- 客户端能连接服务器，完成一次请求/响应演示。
- 公共 `Message`、错误码、角色/权限和数据访问约定已合并。
- 数据库表命名、主键、时间字段和测试数据约定已确定。
- 6 个模块的最小验收场景均已写入 Issue。

## 4. 决策优先级

发生冲突时按以下顺序处理：教师最新要求 > 课程原始材料 > 已评审的架构决策 > 本规划 > 个人习惯。教师要求变化后，由组长当天更新需求基线并通知全员。
