# 四周交付计划

课程模板按半周/上机节点跟踪。下表使用 8 个阶段目标，第一次会议后必须补上实际日期；若教师安排不同，只调整日期，不改变先设计、再纵向打通、再集成冻结的顺序。

| 阶段 | 团队目标 | 每个模块负责人的可验收产物 | 退出条件 |
|---|---|---|---|
| 第1周-目标1 | 需求与分工冻结 | 用例、权限、界面草图、表/DTO/action 清单 | 六模块范围和依赖评审通过；成员表已填写 |
| 第1周-目标2 | 技术骨架打通 | 模块空页面/路由；最小请求处理器 | JDK 8 构建通过；客户端到服务器到数据库完成一次请求 |
| 第2周-目标3 | 基础数据纵向切片 | 每模块至少 1 个查询和 1 个写操作全链路 | 六模块均可从 UI 经 Socket 到数据库并返回 |
| 第2周-目标4 | 核心业务完成 | 各模块主流程与主要异常流程 | 登录授权、学籍 CRUD、选退课、借还、下单、预约可演示 |
| 第3周-目标5 | 跨模块与并发 | 依赖接口、并发/事务用例、审计日志 | 容量/库存/号源无明显超卖；跨模块数据一致 |
| 第3周-目标6 | 功能冻结与集成 | 模块测试、说明、演示数据、缺陷清单 | P0/P1 缺陷清零；形成 `v0.8.0` 候选版本 |
| 第4周-目标7 | 验收与文档 | JavaDoc、使用说明、设计说明、个人材料初稿 | 全新环境按说明部署成功；完成一次限时彩排 |
| 第4周-目标8 | 发布与答辩 | 最终修复、演示脚本、签名/提交材料 | 发布 `v1.0.0`；电子和纸质清单逐项核对 |

## 每周固定节奏

- 上机前：每人更新 Issue 状态、风险和预计完成时间。
- 上机开始 10 分钟：站会，只讨论完成、下一步、阻塞。
- 上机中段：按模块评审/联调，不把所有合并留到当天结束。
- 上机结束前：`main` 构建与冒烟测试，记录演示证据。
- 每周末：组长更新课程进度报告；M4 更新缺陷统计；M6 更新提交清单。

## 优先级与降级策略

- P0：无法启动、数据损坏、登录绕过、核心主流程不可用。立即停止新功能处理。
- P1：必做功能失败或医院主流程失败。功能冻结前必须清零。
- P2：有替代路径的缺陷、体验问题。尽量修复，不影响 P0/P1。
- P3：美化和额外功能。只有六模块核心流程稳定后开展。

若进度落后，按顺序降级：额外动画/皮肤 → 非核心统计 → 图书续借等加分功能 → 复杂医院诊疗记录。不得删除六个模块的最小主流程、授权、异常处理和文档交付。

## 发布节点

- `v0.1.0`：骨架和协议演示。
- `v0.5.0`：六模块主流程初通。
- `v0.8.0`：功能冻结候选版。
- `v0.9.0-rc1`：全新环境验收候选版。
- `v1.0.0`：最终答辩版；提交后仅做经组长批准的阻塞问题修复。
