# 验收与提交清单

## 1. 每个模块的完成定义（DoD）

- [ ] Issue 中的正常、异常和权限验收条件全部通过。
- [ ] 客户端、公共 DTO、服务器端、DAO 和数据脚本形成完整链路。
- [ ] 服务器端执行最终参数校验和权限校验。
- [ ] 数据库约束/并发更新不会产生明显重复或超量数据。
- [ ] 关键类、接口、公开方法有 JavaDoc，代码职责清晰。
- [ ] 有自动测试；无法自动化的 UI 场景有可重复手工步骤和截图。
- [ ] 有最小演示数据、演示账号和模块演示脚本。
- [ ] 模块说明与接口/表结构同步更新。
- [ ] PR 已经他人批准并在 `main` 上构建成功。

## 2. 全系统冒烟测试

- [ ] 全新环境按 README 配置并成功构建。
- [ ] 启动服务器，再启动两个客户端，均能登录和正常退出。
- [ ] 学生账号能查看学籍、选退课、借还书、下单、预约。
- [ ] 教师/管理员权限与学生不同，越权请求被服务器拒绝。
- [ ] 重复选课、库存不足、无可借副本、号源已满等异常提示正确。
- [ ] 客户端异常退出后服务器继续服务其他客户端。
- [ ] 数据库或网络暂时不可用时给出友好提示，恢复后可重新操作。
- [ ] 日志不包含密码，响应不泄漏堆栈和 SQL。
- [ ] 演示数据可恢复，彩排不依赖临时手工修改。

## 3. 课程电子/纸质提交物

依据课程材料建立，提交前按教师最新通知复核：

- [ ] 软件设计说明书（Word）。
- [ ] 小组成员分工汇总表（Word）。
- [ ] 小组进度计划/检查报告（按课程节点）。
- [ ] 班内组间互评表、组内互评表。
- [ ] `vCampusClient.jar`、`vCampusServer.jar`。
- [ ] `vCampus.accdb`，含测试数据；另附建库/初始化材料。
- [ ] 系统使用说明/帮助手册（Word）。
- [ ] 完整 Java 源代码。
- [ ] JavaDoc 生成的 HTML 源代码帮助文档。
- [ ] 小组项目报告（电子版和全员签名纸质版）。
- [ ] 每位成员个人项目小结（电子版和签名纸质版）。
- [ ] 简洁答辩 PPT、演示账号、演示脚本和备份包。

## 5. 答辩彩排

- 总时长按教师当次要求控制，预留提问时间。
- 一人主讲，其他成员都能回答自己模块的需求、表、接口和关键异常处理。
- 演示顺序建议：启动/登录 → 学籍 → 选课 → 图书馆 → 商店 → 医院 → 权限/异常 → 日志或设计亮点。
- 准备本地完整备份、截图/短视频备用证据和简单账号密码。
- 至少进行两次全流程彩排：一次功能导向，一次严格计时并模拟提问。
