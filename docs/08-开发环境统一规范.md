# 开发环境统一规范

## 1. 团队统一版本

| 项目 | 统一标准 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11 x64 | 与 Access 和机房环境保持接近 |
| JDK | Eclipse Temurin 8u502-b07，Windows x64，HotSpot，JDK 包 | 必须是 JDK，不要只装 JRE |
| Java 语言/字节码 | Java 8 | 禁止使用 Java 9+ 语法和 API |
| Maven | Apache Maven 3.9.16 | 不使用预览版 Maven 3.10 或 Maven 4 |
| Git | Git for Windows 2.x | 使用仓库的 `.gitattributes` 统一换行 |
| IDE | IntelliJ IDEA 或 Eclipse | IDE 可不同，但项目 SDK、语言级别和 Maven Runner 必须是 JDK 8 |
| 编码 | UTF-8 | Java、XML、Markdown、SQL 全部统一 |
| 时区 | Asia/Shanghai | Maven JVM 已通过 `.mvn/jvm.config` 固定 |
| 数据库 | Access `.accdb`，文件名 `vCampus.accdb` | Access/驱动具体版本须再与机房确认 |

团队应让 6 人使用同一份 JDK 8 和 Maven 安装包，并在群文件中保存安装包及 SHA-256，避免下载到不同架构或 JRE 包。

## 2. JDK 8 是什么

JDK（Java Development Kit）是 Java 开发工具包，包括：

- `java`：运行编译后的程序。
- `javac`：把 `.java` 源代码编译为 `.class`。
- `javadoc`：生成课程要求的 HTML 源代码帮助文档。
- Java 8 标准库和调试、打包等工具。

“JDK 8”表示本项目使用 Java 8 的语法、标准库和字节码。版本输出通常以 `1.8.0_xxx` 开头；这里统一的 Temurin 8u502 输出应接近 `1.8.0_502`。

## 3. JDK 25 能不能用

可以保留，但不能作为本项目的默认 JDK。原因是：

- JDK 25 默认允许使用 Java 25 语法，JDK 8 无法编译。
- 即使只设置 `source/target=8`，仍可能误用 Java 8 中不存在的新 API。
- 教师机房或最终验收若只安装 JDK 8，错误通常到交付时才暴露。

JDK 25 的 `javac --release 8` 能帮助限制语言、字节码和标准 API，但这只是兼容手段，不能代替在真实 JDK 8 上构建和运行。为了降低六人协作风险，本仓库的 Maven 检查会拒绝 JDK 25，并要求 Maven 实际运行在 JDK 8 上。

电脑可以同时安装 JDK 8 和 JDK 25：其他项目继续使用 JDK 25，本项目在 IDE 的 Project SDK 和 Maven Runner 中单独选择 JDK 8 即可，不需要卸载 JDK 25。

## 4. Windows 安装与配置

### 4.1 安装 JDK 8

从 Eclipse Adoptium 官方发布页下载 `Temurin 8 / JDK / Windows / x64 / HotSpot`，团队锁定 `8u502-b07`。安装时可选择自动设置 `JAVA_HOME` 和加入 `PATH`；如果没有选择，手工设置：

```powershell
# 示例路径以实际安装目录为准；不要照抄不存在的目录。
[Environment]::SetEnvironmentVariable(
    'JAVA_HOME',
    'C:\Program Files\Eclipse Adoptium\jdk-8.0.502.7-hotspot',
    'User'
)
```

在用户 `Path` 中把 `%JAVA_HOME%\bin` 放在 JDK 25 的 `bin` 前面。关闭并重新打开终端，然后检查：

```powershell
java -version
javac -version
```

两项都应显示 `1.8.0_502`，不能一个是 8、另一个是 25。

### 4.2 安装 Maven

从 Apache Maven 官方页面下载 `apache-maven-3.9.16-bin.zip`，解压到不含中文和空格的固定目录，例如 `D:\tools\apache-maven-3.9.16`。新增用户变量 `MAVEN_HOME`，并把 `%MAVEN_HOME%\bin` 加入 `Path`。

重新打开终端：

```powershell
mvn -version
```

必须同时看到 `Apache Maven 3.9.16` 和 `Java version: 1.8.0_502`。如果 Maven 显示 Java 25，说明 `JAVA_HOME` 或 IDE 的 Maven Runner 仍选错。

## 5. IDE 设置

### IntelliJ IDEA

- Project SDK：Temurin 8。
- Project language level：8 - Lambdas, type annotations 等 Java 8 级别。
- Maven Runner JRE：Project SDK / Temurin 8。
- 编码：Global、Project、Properties 均为 UTF-8。
- 通过根目录 `pom.xml` 导入项目，不手工建立互不一致的普通 Java 工程。

### Eclipse

- Installed JREs：添加 Temurin 8，并设为项目默认。
- Compiler compliance level：1.8。
- Maven：使用 Maven 3.9.16，运行 JRE 选择 Temurin 8。
- Workspace 和项目文本编码：UTF-8。

不要提交 `.idea`、`.classpath`、`.project` 等个人 IDE 文件，仓库已统一忽略。

## 6. 每位成员首次克隆后的检查

在仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/check-environment.ps1
mvn validate
```

两个命令都通过后，才能领取开发 Issue。若脚本提示 JDK 25，不要删除 JDK 25，只需把当前项目和 Maven 切换到 JDK 8。

## 7. 仓库自动约束

- `.java-version` 声明项目 Java 主版本为 8。
- `pom.xml` 固定 Java release/source/target 为 8，并要求 Maven 3.9.16、JDK 8。
- `.mvn/jvm.config` 固定 UTF-8 和 Asia/Shanghai 时区。
- `.editorconfig` 统一缩进、编码和文件结尾。
- `.gitattributes` 统一文本换行，并保护 Word、Access、JAR 等二进制文件。
- `scripts/check-environment.ps1` 在开发前快速检查 Java、编译器、Maven、JAVA_HOME 和 Git。

## 8. 尚待教师确认

Access 的准确版本、机房 Windows 版本、是否允许使用 UCanAccess/H2/SQLite，以及最终运行机器是否已有额外 JDBC 驱动。这些结论确认后写入 ADR，不由成员各自决定。
