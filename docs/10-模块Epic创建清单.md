# 六个模块 Epic 创建清单

当前远程仓库尚无 Issue。组长需要在 GitHub 使用“模块任务”模板创建以下六个 Epic，并按小组已经确认的分工直接设置 `Assignee`。

入口：[新建模块任务](https://github.com/qlaxyy/JAVA-Campus-software/issues/new?template=module-task.yml)

## 创建步骤

1. 打开“新建模块任务”入口。
2. 按下方内容填写标题、目标、范围、验收条件、契约和依赖。
3. 在右侧 `Assignees` 中选择该模块已经确定的负责人。
4. 创建完成后把六个 Issue 链接发到小组群，由成员确认分工和验收范围。
5. 组长检查六个模块恰好各有一位负责人且人员不重复。

下拉框中只选择六个业务模块。`公共/网络`、`数据库`、`文档/发布` 保留给后续横向任务，不在本轮创建额外 Epic，也不改变“一人一个业务模块”的初始分工。

## Epic 1：用户管理

标题：`[用户管理] 模块 Epic：认证、账户与权限`

用户故事/目标：

> 为虚拟校园提供统一账户、登录会话和服务器端授权能力，所有其他模块复用同一用户身份，不重复实现登录。

范围内：注册、注销、登录、登出、账户启停、角色/权限、会话校验、登录审计。范围外：第三方登录、短信、邮件、真实身份认证。

验收条件：

- [ ] 正常：用户可注册、登录、登出并查看当前账户信息。
- [ ] 正常：管理员可维护账户状态和角色/权限。
- [ ] 异常：重复账号、错误密码、已停用账户、过期会话有明确错误码。
- [ ] 权限：所有受保护请求均在服务器端校验，客户端隐藏按钮不能代替授权。
- [ ] 安全：密码不明文存储，日志和响应不泄漏密码或堆栈。
- [ ] 证据：有测试、界面截图、接口/action 清单和演示账号说明。

页面/action/DTO/表：登录、注册、账户管理页面；`USER.REGISTER/LOGIN/LOGOUT/GET_CURRENT/UPDATE_ROLE`；用户、登录、角色权限相关 DTO；`tblUser` 及必要权限/会话表。

依赖与风险：最先确定公共会话和权限接口；被所有模块依赖；公共 DTO 变更必须通知全员。

## Epic 2：学生学籍

标题：`[学生学籍] 模块 Epic：学生与学籍信息管理`

用户故事/目标：

> 为学生、教师和管理员提供统一学籍信息，并向选课、图书馆和医院提供稳定的学生身份查询能力。

范围内：学生、院系、专业、班级、学籍状态；学生查看允许的信息；管理员增查改停用。范围外：招生、缴费、毕业审核等复杂教务流程。

验收条件：

- [ ] 正常：管理员可以新增、查询、修改和停用学生记录。
- [ ] 正常：学生只能查看或修改被允许的个人信息。
- [ ] 异常：学号重复、关联院系/专业/班级不存在时拒绝保存。
- [ ] 权限：普通学生不能修改他人学籍或关键学籍状态。
- [ ] 一致性：被其他模块引用的学生记录不直接物理删除。
- [ ] 证据：有数据字典、测试、界面截图和跨模块只读查询说明。

页面/action/DTO/表：个人学籍、学生管理、院系/专业/班级页面；`STUDENT.GET_PROFILE/SEARCH/CREATE/UPDATE/DISABLE`；学生/班级等 DTO；`tblStudent/tblDepartment/tblMajor/tblClass`。

依赖与风险：依赖用户 `userId`；向选课、图书馆、医院提供只读学生状态接口；避免其他模块直接更新学籍表。

## Epic 3：选课系统

标题：`[选课系统] 模块 Epic：课程、选退课、课表与成绩`

用户故事/目标：

> 学生能够查询开课、完成选退课并查看课表和成绩，教师/管理员能够维护课程和成绩。

范围内：课程、开课班、教师、容量、时间地点、选退课、课表、成绩。范围外：复杂培养方案、排课优化和在线教学。

验收条件：

- [ ] 正常：学生可查询课程、选课、退课并查看个人课表和成绩。
- [ ] 正常：教师/管理员可维护授权范围内的课程和成绩。
- [ ] 异常：重复选课、容量已满、时间冲突、非开放阶段、非法成绩被拒绝。
- [ ] 权限：学生不能修改成绩，教师只能修改授权课程成绩。
- [ ] 并发：多个学生同时选最后名额时不能超出容量。
- [ ] 证据：有流程图、表结构、并发/异常测试和主流程截图。

页面/action/DTO/表：课程查询、选课、个人课表、成绩管理页面；`COURSE.SEARCH/ENROLL/DROP/GET_SCHEDULE/SET_SCORE`；课程/开课/选课 DTO；课程、开课、选课、成绩相关表。

依赖与风险：依赖用户权限和学籍有效状态；容量检查与写入必须原子处理。

## Epic 4：图书馆

标题：`[图书馆] 模块 Epic：馆藏、借阅与归还`

用户故事/目标：

> 学生能够查询馆藏并完成借阅、归还，管理员能够维护图书和库存。

范围内：图书、分类、馆藏/可借数量、查询、借阅、归还、借阅记录；续借可作为加分项。范围外：真实罚款支付、馆际互借和推荐系统。

验收条件：

- [ ] 正常：用户可检索图书、查看可借数量和个人借阅记录。
- [ ] 正常：满足条件时可借阅、归还，管理员可维护图书和库存。
- [ ] 异常：无库存、重复借阅、超过借阅上限、记录不存在时拒绝操作。
- [ ] 权限：普通用户不能直接修改馆藏数量。
- [ ] 并发：最后一本书不能被两个客户端同时借走。
- [ ] 证据：有表结构、状态流转、测试、界面截图和演示数据。

页面/action/DTO/表：馆藏检索、我的借阅、借还管理、图书维护页面；`LIBRARY.SEARCH/BORROW/RETURN/MY_LOANS/UPDATE_BOOK`；图书/馆藏/借阅 DTO；相关数据库表。

依赖与风险：依赖用户身份和学生有效状态；库存检查与借阅写入必须原子处理。

## Epic 5：商店

标题：`[商店] 模块 Epic：商品、库存、购物车与订单`

用户故事/目标：

> 用户能够浏览商品、管理购物车并创建/查询订单，管理员能够维护商品和库存。

范围内：分类、商品、价格、库存、上下架、购物车、订单、取消和模拟支付状态。范围外：真实支付、银行接口、物流和退款结算。

验收条件：

- [ ] 正常：用户可查询商品、加入购物车、下单、查询和按规则取消订单。
- [ ] 正常：管理员可维护商品、价格、库存和上下架状态。
- [ ] 异常：库存不足、商品下架、数量非法、订单状态不允许时拒绝操作。
- [ ] 权限：订单只能由所属用户查看，管理员操作经过授权。
- [ ] 一致性：下单时服务器重新校验价格和库存，失败不留下半完成订单。
- [ ] 证据：有订单状态图、并发库存测试、界面截图和演示数据。

页面/action/DTO/表：商品列表、购物车、订单、商品管理页面；`SHOP.SEARCH/ADD_CART/CREATE_ORDER/CANCEL_ORDER/MY_ORDERS`；商品/购物车/订单 DTO；相关数据库表。

依赖与风险：依赖用户身份；不依赖未选择的银行模块；库存扣减必须原子处理。

## Epic 6：医院

标题：`[医院] 模块 Epic：医生排班与预约`

用户故事/目标：

> 学生能够查询科室、医生和号源并预约/取消，管理员能够维护医生与排班。

范围内：科室、医生、排班/号源、预约、取消、预约记录；诊疗记录只保留最小必要范围。范围外：真实医保、收费、药品、检验和完整电子病历。

验收条件：

- [ ] 正常：学生可查询科室、医生、可用时段，预约、取消并查看记录。
- [ ] 正常：管理员可维护医生、科室和排班/号源。
- [ ] 异常：重复预约、号源已满、过期时段、非法取消被拒绝。
- [ ] 权限：用户只能查看自己的预约；敏感信息按最小权限返回。
- [ ] 并发：最后一个号源不能被两个客户端同时预约。
- [ ] 证据：有预约状态/流程图、并发测试、界面截图和演示数据。

页面/action/DTO/表：科室医生查询、预约、我的预约、排班管理页面；`HOSPITAL.SEARCH_SLOTS/BOOK/CANCEL/MY_APPOINTMENTS/UPDATE_SCHEDULE`；医生/排班/预约 DTO；相关数据库表。

依赖与风险：依赖用户身份和学生状态；禁止在公开仓库存放真实病历或个人隐私。
