# 公共工程骨架与运行

## 1. 目的

本骨架为六个业务模块提供唯一的公共起点，先验证 JDK、Maven、Swing、Socket、对象序列化和服务器线程池可以协同工作。PR #7 最初只实现 `COMMON.PING`；并行开发基线随后加入可替换的开发期登录/会话，但仍不包含 Access 数据库和六模块正式业务功能。

## 2. 模块

```text
vcampus-parent
├─ vcampus-common   公共 Request/Response、Action 和错误码
├─ vcampus-server   Socket 接入、固定线程池和请求分发
└─ vcampus-client   网络客户端、Swing 主窗口
```

依赖方向：`client → common`、`server → common`。业务代码不得让 `common` 反向依赖客户端或服务器端。

## 3. 第一次导入 IDEA

1. 拉取最新分支并用 IntelliJ IDEA Community Edition 打开仓库根目录。
2. 通过根 `pom.xml` 加载 Maven 工程，确认 Maven 面板显示 parent、common、server、client。
3. Project SDK、Language level、Maven Importer 和 Maven Runner 均选择 JDK 25。
4. 在 IDEA 终端运行 `mvn clean verify`，首次运行会从 Maven Central 下载插件和 JUnit 依赖。

## 4. 运行 PING/PONG

### IDEA 方式

1. 打开 `vcampus-server/src/main/java/edu/seu/vcampus/server/ServerMain.java`，运行 `main`。
2. 服务器控制台应显示 `Virtual Campus server started on port 8888.`。
3. 打开 `vcampus-client/src/main/java/edu/seu/vcampus/client/ClientMain.java`，运行 `main`。
4. 客户端启动后先使用 `student001 / Student@123` 登录；登录前不显示业务模块。
5. 登录成功后左侧显示业务模块入口，顶部不再显示“用户登录”入口。
6. 点击“测试服务器连接”，界面显示 `连接成功：PONG` 即通过；再点击右上角“退出登录”返回登录页。完整演示账号和限制见 `docs/13-开发期基础登录与会话.md`。

### Windows 命令行方式

先在根目录执行 `mvn clean package`，再打开两个 PowerShell。

服务器端：

```powershell
java -cp "vcampus-common\target\classes;vcampus-server\target\classes" edu.seu.vcampus.server.ServerMain
```

客户端：

```powershell
java -cp "vcampus-common\target\classes;vcampus-client\target\classes" edu.seu.vcampus.client.ClientMain
```

服务器端和客户端默认连接 `127.0.0.1:8888`。只有需要本机实验时才通过启动参数修改主机或端口，不把个人地址写进公共代码。

## 5. 自动化验证

`vcampus-client` 中的集成测试会使用随机空闲端口启动真实服务器并验证：

- `COMMON.PING` 返回成功和 `PONG`。
- 未知 Action 返回 `COMMON_UNKNOWN_ACTION`。
- 演示账号登录、查询会话和登出。
- 错误密码不建立会话。

每次提交 PR 前运行：

```powershell
mvn clean verify
```

只有出现 `BUILD SUCCESS` 且测试失败数为 0，才可以提交评审。

## 6. 六模块扩展位置

并行开发基线为每个模块建立了独立的 common、client、server、设计文档和数据字典位置。服务器 action 由本模块 `ServerModule` 注册到 `ActionRouter`，客户端页面由本模块 `ClientModule` 提供。共享 `ClientContext` 自动携带 token，`ServerContext.sessions()` 提供统一会话查询。当前开工步骤统一见 [当前开发通知](团队开发通知.md)。

## 7. 后续扩展规则

- 新业务 Action 常量和 DTO 进入 `vcampus-common` 的本模块包；错误码按模块前缀定义，客户端和服务器在同一 PR 中适配。
- Swing 网络调用必须使用 `SwingWorker` 等后台方式，不能阻塞 EDT。
- 服务器业务处理进入固定线程池，异常连接不能终止接收线程。
- 当前采用“一次连接处理一次请求”的最小模型；开发期会话见 ADR-0008，长连接、对象过滤和协议版本须通过后续 ADR 决定。
- 数据库尚未接入。Access/JDBC 决策通过前，各模块可以完成界面、DTO/action、服务接口、内存演示链路和数据字典，不提交个人二进制数据库。
