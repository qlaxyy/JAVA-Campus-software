# 开发期基础登录与会话

## 1. 目的与状态

本功能只为六模块并行开发提供统一的用户身份、角色和会话 token，使其他模块不用等待 Access 用户表就能开发受保护请求。它是“开发基线”，不是用户管理模块的最终验收实现。

当前已经实现：

- `USER.LOGIN`：校验虚构演示账号并生成随机会话 token。
- `USER.CURRENT_SESSION`：根据 token 返回当前用户和角色。
- `USER.LOGOUT`：服务端注销 token，客户端清除本地会话。
- `STUDENT`、`TEACHER`、`ADMIN` 三种基础角色。
- 登录 Swing 页面和共享 `ClientContext`。
- 正确登录/会话/登出、错误密码两个真实 Socket 集成测试。

## 2. 虚构演示账号

| 角色 | 用户名 | 密码 | 用途 |
|---|---|---|---|
| 学生 | `student001` | `Student@123` | 学生端功能开发 |
| 教师 | `teacher001` | `Teacher@123` | 教师端功能开发 |
| 管理员 | `admin` | `Admin@123` | 管理功能开发 |

这些是公开仓库专用假账号，不得改成成员真实密码，也不得在其他网站复用。

## 3. 运行验证

1. 先运行 `ServerMain`，确认服务器监听 8888 端口。
2. 再运行 `ClientMain`，启动界面应只显示账户名、密码和登录按钮，不显示业务模块。
3. 使用任一演示账号登录；成功后进入主界面，右上角显示用户名称和角色，左侧显示业务模块。
4. 点击右上角“退出登录”，应返回登录页并清除本地会话。

自动验证仍使用：

```powershell
mvn clean verify
```

## 4. 其他客户端模块怎样携带登录状态

每个 `ClientModule.createView` 都会收到共享 `ClientContext`。模块发请求时使用：

```java
Response response = context.send(MyModuleActions.SOME_ACTION, requestDto);
```

`ClientContext` 会自动把当前 token 放入 `Request`。不要在模块内保存第二份 token，不要自己重新实现登录窗口。

需要根据当前角色调整界面时可读取：

```java
context.currentSession().ifPresent(session -> {
    Role role = session.getRole();
});
```

客户端隐藏按钮只改善体验，不能代替服务器授权。

## 5. 其他服务器模块怎样校验登录和角色

每个 `ServerModule.registerHandlers` 都会收到共享 `ServerContext`。受保护 handler 先读取会话：

```java
return context.sessions().findSession(request.getToken())
        .map(session -> handleAuthenticated(request, session))
        .orElseGet(() -> Response.failure(
                request.getRequestId(),
                ErrorCodes.AUTH_REQUIRED,
                "Please log in first."));
```

需要管理员权限时继续检查 `session.getRole() == Role.ADMIN`，不满足时返回 `AUTH_FORBIDDEN`。禁止只在 Swing 页面隐藏按钮而不做服务器端判断。

## 6. 当前安全边界与后续替换

- 演示用户和会话当前只保存在服务器内存中，重启服务器后会话全部失效。
- 客户端发送 SHA-256 开发证明而不是原始密码；该证明仍可能被重放，不能替代 TLS、随机挑战和正式密码协议。
- 当前会话没有过期时间、刷新、登录次数限制和完整权限集合。
- 用户模块负责人后续必须把账号读取替换为 Access DAO，把密码保存替换为带盐慢哈希，并补充账户状态、会话过期、权限和审计。
- 其他模块只依赖 `SessionInfo`、`ClientContext` 和 `ServerContext.sessions()`，不得依赖 `InMemoryAuthenticationService` 的内部实现。

最终认证方案形成并评审后，应保留现有 action/DTO 的兼容性或在契约 PR 中同步迁移所有模块。
