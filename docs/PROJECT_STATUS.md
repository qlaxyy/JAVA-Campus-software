# 项目当前状态

更新时间：2026-09-07

本文只保留“现在做到哪里、下一步做什么”。具体提交过程和讨论以 Git、Pull Request、Issue 为准。

## 1. 已完成的公共基础

- Maven 三模块骨架和统一启动入口。
- Swing 统一登录、按会话权限显示的校园服务导航、Socket 请求/响应、Action 路由。
- 登录页和登录后工作区已统一为青绿色视觉主题，包含账号状态、修改密码、退出登录和服务器连接检测。
- 已建立全系统《软件设计说明书》汇总框架，公共架构和用户登录部分已完成，其余子系统章节等待负责人材料。
- Access 一卡通账号持久化、带空闲和绝对有效期的内存 token 会话、`Role` 与 `AdminScope` 基础授权；普通一卡通号采用“4 位年份 + `0001`—`9999`”，`20260000` 保留给演示超级管理员，普通账号只允许 0–1 个子系统管理权。
- 新增 `20260008` 普通教师演示账号；用户模块不赋予全局教师角色，教师资格仍由选课子系统使用 `userId` 绑定自己的教师名单。
- 六个客户端/服务器模块的注册结构。
- 医院医生新增采用分类申请审核：已有账号由医院明确选择并校验，外来医生由用户模块在批准后按当年最大流水号加一生成一卡通号；医院管理员可在申请记录中取得审核状态和生成的一卡通号，再交付给医生。申请和档案保存在 Access。
- 登录失败保护：同一一卡通号在 10 分钟内连续失败 5 次后暂停登录 5 分钟；成功登录会清除失败记录，失败响应不暴露账号是否存在。
- 单服务器、多客户端网络链路已实现；跨电脑统一使用 Radmin VPN，应用层保持 TCP Socket。自动测试验证服务器监听全部网卡、并发客户端具有独立 token，单个客户端退出不会结束其他客户端的会话。Radmin VPN 真机联调仍需在两台真实设备上验收。
- 当前版本完整执行 Maven 测试，共 140 项测试通过（服务器 66 项、客户端 74 项）。

## 3. 当前优先级

1. 学籍、选课、图书馆、商店和医院逐步把内存 Repository 替换为 Access DAO。
2. 补齐每个受保护 Action 的登录、管理权或业务资格校验。
3. 完成正常、异常、越权和并发场景测试。
4. 在两台真实电脑和全新环境验证客户端 JAR、服务器 JAR、Radmin VPN、防火墙和单机数据库部署流程。

## 4. 主要风险

| 风险 | 当前处理 |
|---|---|
| Access/JDBC 集成晚，集中暴露问题 | 先做单模块最小读写验证，再逐模块迁移 |
| 模块只完成页面，没有服务器和数据链路 | PR 必须展示完整纵向链路和验证证据 |
| 只隐藏按钮，没有服务器授权 | 所有保护操作都在服务器 Action 再校验 |
| 库存、容量、号源并发出错 | 写操作放在服务器，并增加并发测试 |
| common 契约频繁变化造成冲突 | 公共协议小步修改，先评审再合并 |
