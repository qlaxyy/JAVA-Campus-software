# 项目当前状态

更新时间：2026-09-04

本文只保留“现在做到哪里、下一步做什么”。具体提交过程和讨论以 Git、Pull Request、Issue 为准。

## 1. 已完成的公共基础

- Maven 三模块骨架和统一启动入口。
- Swing 统一登录、按会话权限显示的校园服务导航、Socket 请求/响应、Action 路由。
- 登录页和登录后工作区已统一为青绿色视觉主题，包含账号状态、退出登录和服务器连接检测。
- 已建立全系统《软件设计说明书》汇总框架，公共架构和用户登录部分已完成，其余子系统章节等待负责人材料。
- Access 一卡通账号持久化、内存 token 会话、`Role` 与 `AdminScope` 基础授权；一卡通号采用“4 位年份 + 4 位流水号”。
- 六个客户端/服务器模块的注册结构。
- 医院医生新增采用分类申请审核：已有账号由医院明确选择并校验，外来医生由用户模块在批准后按当年最大流水号加一生成一卡通号；医院管理员可在申请记录中取得审核状态和生成的一卡通号，再交付给医生。申请和档案保存在 Access。
- 当前本地版本执行完整 Maven 测试，共 127 个测试通过。

## 3. 当前优先级

1. 学籍、选课、图书馆、商店和医院逐步把内存 Repository 替换为 Access DAO。
2. 补齐每个受保护 Action 的登录、管理权或业务资格校验。
3. 完成正常、异常、越权和并发场景测试。
4. 在全新环境验证客户端 JAR、服务器 JAR 和数据库的部署流程。

## 4. 主要风险

| 风险 | 当前处理 |
|---|---|
| Access/JDBC 集成晚，集中暴露问题 | 先做单模块最小读写验证，再逐模块迁移 |
| 模块只完成页面，没有服务器和数据链路 | PR 必须展示完整纵向链路和验证证据 |
| 只隐藏按钮，没有服务器授权 | 所有保护操作都在服务器 Action 再校验 |
| 库存、容量、号源并发出错 | 写操作放在服务器，并增加并发测试 |
| common 契约频繁变化造成冲突 | 公共协议小步修改，先评审再合并 |
