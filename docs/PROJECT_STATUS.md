# 项目当前状态

更新时间：2026-08-30

本文只保留“现在做到哪里、下一步做什么”。具体提交过程和讨论以 Git、Pull Request、Issue 为准。

## 1. 已完成的公共基础

- Maven 三模块骨架和统一启动入口。
- Swing 统一登录、按会话权限显示的校园服务导航、Socket 请求/响应、Action 路由。
- 登录页和登录后工作区已统一为青绿色视觉主题，包含账号状态、退出登录和服务器连接检测。
- 内存账号认证、token 会话、`Role` 与 `AdminScope` 基础授权。
- 六个客户端/服务器模块的注册结构。
- 当前本地版本执行完整 Maven 测试，共 33 个测试通过。

| 商店 | 模块入口 | 商品、购物车、订单主流程、库存并发和 DAO |
| 医院 | 科室/号源查询，患者、医生、管理员模式入口 | 预约主流程、医生与管理功能、DAO、隐私与并发验证 |

## 3. 当前优先级

1. 先让图书馆和商店形成第一条完整客户端—服务器链路。
2. 各模块把现有内存 Repository 逐步替换为 Access DAO。
3. 补齐每个受保护 Action 的登录、管理权或业务资格校验。
4. 完成正常、异常、越权和并发场景测试。
5. 在全新环境验证客户端 JAR、服务器 JAR 和数据库的部署流程。

## 4. 主要风险

| 风险 | 当前处理 |
|---|---|
| Access/JDBC 集成晚，集中暴露问题 | 先做单模块最小读写验证，再逐模块迁移 |
| 模块只完成页面，没有服务器和数据链路 | PR 必须展示完整纵向链路和验证证据 |
| 只隐藏按钮，没有服务器授权 | 所有保护操作都在服务器 Action 再校验 |
| 库存、容量、号源并发出错 | 写操作放在服务器，并增加并发测试 |
| common 契约频繁变化造成冲突 | 公共协议小步修改，先评审再合并 |

- Access 持久化、管理功能与跨模块联调：未完成。
