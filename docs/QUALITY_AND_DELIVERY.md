# 质量与交付清单

## 1. 一个功能什么时候算完成

- 客户端页面可以发起真实请求，不用硬编码结果冒充服务器响应。
- 服务器完成登录、权限、参数和业务规则校验。
- 数据通过 Repository/DAO 读写，Swing 页面不直接执行 SQL。
- 正常、异常和越权流程有自动测试或清晰的重复验证步骤。
- Action、DTO、数据表或设计有变化时，同一 PR 更新唯一对应文档。
- `mvn clean verify` 通过，PR 由非作者完成评审。

## 2. 测试层次

| 层次 | 重点 |
|---|---|
| 单元测试 | Service 规则、边界值、状态变化 |
| 服务器模块测试 | Action 路由、DTO 校验、登录和权限 |
| Repository/DAO 测试 | 查询、约束、事务或补偿、异常映射 |
| 集成测试 | 客户端—Socket—服务器完整请求链路 |
| 手工验收 | 页面操作、错误提示、角色/模式切换、打包运行 |

库存、选课容量和医院号源等竞争资源必须增加并发验证，不能只测单用户顺序操作。

## 3. 缺陷等级

| 等级 | 含义 | 发布要求 |
|---|---|---|
| P0 | 数据严重损坏、安全事故、系统完全不可用 | 立即处理，禁止发布 |
| P1 | 核心流程失败、越权、结果明显错误 | 发布前清零 |
| P2 | 非核心功能错误或有明确绕行方案 | 评估后修复或记录 |
| P3 | 文案、样式和轻微体验问题 | 不阻塞核心验收 |

## 4. PR 必须提供的证据

- 改了什么，以及对应 Issue/Epic。
- 如何验证，附测试命令结果或手工步骤。
- 是否改变 common、数据库、权限或其他模块。
- 页面变化附截图；协议变化列出 Action、请求 DTO、响应 DTO 和错误码。
- 不提交密钥、真实个人信息、IDE 私有配置、个人数据库或构建产物。

## 5. 系统验收

- 新环境按根目录 README 可以启动服务器和客户端。
- 六个模块都有可演示的普通主流程，管理功能按授权可用。
- 未登录、无管理权或无业务资格的请求被服务器拒绝。
- 服务器异常不会导致客户端无响应，用户能看到可理解的错误信息。
- Access 数据、唯一约束和跨模块 ID 关系与数据字典一致。
- 打包产物、JavaDoc、数据库和课程文档内容相互一致。

## 6. 最终提交物

- 完整源码和可复现的 Maven 构建。
- 可运行的客户端 JAR、服务器 JAR 与启动说明。
- 初始化后的 `vCampus.accdb` 和必要演示数据。
- JavaDoc 与课程要求的需求、设计、测试、用户手册和小组报告。
- 演示脚本、答辩材料及已知限制说明。

最终发布前冻结新功能，只修复阻塞验收的问题；至少在一台未参与开发的电脑上完成一次全流程彩排。
