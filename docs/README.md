# 项目文档导航

文档按用途分层。组员不需要每天阅读全部文件；首页、当前通知和自己的模块文档是日常入口，其余材料在需要时查阅或由组长维护。

## 组员日常使用

| 需要做什么 | 看哪里 |
|---|---|
| 查看当前一轮任务 | [当前开发通知](团队开发通知.md) |
| 学习分支、提交和 PR | [贡献指南](../CONTRIBUTING.md) |
| 运行客户端和服务器 | [公共工程骨架与运行](11-公共工程骨架与运行.md) |
| 了解登录和 Token | [开发期基础登录与会话](13-开发期基础登录与会话.md) |
| 查看本模块设计 | [`modules/`](modules/) |
| 查看本模块数据字段 | [`database/schema/`](../database/schema/) |

## 遇到具体问题时查阅

- [需求基线](01-需求基线.md)：判断功能是不是课程要求。
- [总体架构与接口约定](03-总体架构与接口约定.md)：新增 Action、DTO、错误码，或处理权限、并发、数据库时查阅。
- [GitHub 协作规范](05-GitHub协作规范.md)：需要完整 Issue、分支、PR 和评审规则时查阅。
- [开发环境统一规范](08-开发环境统一规范.md)：JDK、Maven、Git 或 IDEA 配置有问题时查阅。
- [验收与提交清单](06-验收与提交清单.md)：阶段验收和最终提交前查阅。

## 教师原始材料

[`课程原始材料/`](课程原始材料/) 保存教师要求，优先级高于项目内部规划。项目启动清单和旧版开工说明已停止维护；已发生事实保存在项目推进日志和 Git 历史中。

## 维护原则

- “这一轮做什么”只更新 `团队开发通知.md`。
- 永久 Git 规则只更新 `CONTRIBUTING.md` 或 `05-GitHub协作规范.md`。
- 架构规则只更新 `03-总体架构与接口约定.md`；重大决定同时记录 ADR。
- 已发生的进展只追加到 `progress/PROJECT_LOG.md`，不要把历史复制到通知里。
- 已发生的事实保留在推进日志和 Git 历史中，不再为同一规则维护多份现行说明。
