# ADR-0002：通过 GitHub Issue Assignee 自主认领模块

- 状态：被 ADR-0005 取代
- 日期：2026-08-24
- 决策范围：六人模块分工、公共职责和贡献留痕

## 背景

项目有六位成员和六个业务模块。具体负责人尚未确定，成员希望自行领取任务。公开仓库不适合维护学号、联系方式等个人信息，固定 M1-M6 编号也会在交换任务时造成文档过时。

## 决定

- 为用户、学籍、选课、图书馆、商店、医院分别创建一个模块 Epic Issue。
- Issue 创建时不预设负责人，成员先评论“认领该模块”，再把自己设置为 Assignee。
- 六个 Epic 必须恰好各有一位主 Assignee，且同一成员不能同时主责两个模块。
- 模块交换、负责人变化和公共职责均通过 Issue 记录，不以群聊或固定文档名单为准。
- 最终分工、个人小结和贡献统计从 Assignee、PR、评审和测试记录提取；学号等课程所需隐私信息在线下分工表补充。

## 备选方案

### 由组长直接指定

分配速度快，但不符合成员自主领取意愿，也不利于承诺和后续调整。未采用。

### 在 Markdown 表中填写人员

查看直观，但容易过时并暴露个人信息。未采用。

### 使用长期个人分支代表负责人

无法清晰记录需求、验收和任务状态，并增加合并风险。未采用。

## 影响与迁移

- 2026-08-24 分工已由小组确认，改由组长直接设置 Assignee；现行规则见 ADR-0005。本文件保留为历史决定。
- 在六个模块 Issue 创建并认领前，业务责任边界尚未正式生效。
- PR、追踪表和最终材料必须链接对应 Issue。
- 若成员退出或交换模块，只修改 Assignee并留下说明，不改写历史记录。
