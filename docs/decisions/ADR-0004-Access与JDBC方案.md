# ADR-0004：Access 与 JDBC 访问方案

- 状态：提议
- 日期：2026-08-24
- 决策范围：数据库版本、驱动、连接和初始化

## 背景

课程材料以 Access 和 `vCampus.accdb` 为主要验收数据库，同时提到 H2、SQLite 等文件型数据库可选。当前尚未确认机房 Access 版本、JDK 25 下的 JDBC 驱动、是否允许不依赖 Office/ODBC 的连接方式，以及最终机器的安装条件。

## 待回答问题

1. 教师是否要求最终必须提交 Access `.accdb`，还是允许 H2/SQLite？
2. 机房 Windows、Access/Office 的准确版本和位数是什么？
3. JDK 25 下选择哪个 JDBC 驱动及版本？
4. 驱动是否能在未安装 Access 的机器直接读写 `.accdb`？
5. 事务、并发和约束支持是否满足课程容量/库存/号源场景？
6. 如何通过文本脚本/数据字典协作，避免多人合并二进制数据库冲突？

## 候选方案

### Access + 纯 Java JDBC 驱动

与课程交付格式一致，可能减少 ODBC/位数配置；需验证 JDK 25 兼容性、依赖、事务和中文字段。

### Access + ODBC/JDBC 桥接方案

可能依赖本机 Office/驱动和 32/64 位匹配，部署风险较高；需实际机房验证。

### 开发/测试使用 H2 或 SQLite，最终导出 Access

自动测试较方便，但可能产生 SQL 方言和最终数据差异；只有教师允许且转换流程可重复时采用。

## 决策门禁

在以下证据完成前，本 ADR 不得标记为“通过”：

- [ ] 教师/机房数据库要求已确认并记录。
- [ ] JDK 25 最小连接原型可以建表、增查改删、事务提交/回滚和中文读写。
- [ ] 两个客户端并发修改容量/库存/号源的策略得到验证。
- [ ] 新机器按 README 能复现连接。
- [ ] 驱动许可证和依赖可随项目正常使用。
- [ ] 建库、初始化和演示数据方案明确。

## 暂行约束

- 验收数据库名称保留 `vCampus.accdb`。
- 模块负责人先提交表设计和文本数据字典，不各自提交个人二进制数据库。
- 在 ADR 通过前，不在业务代码中散落具体驱动类和连接字符串。
