# ADR-0005：组长按已确认分工统一设置模块负责人

- 状态：通过
- 日期：2026-08-24
- 取代：ADR-0002
- 决策范围：六人模块分工与 GitHub 负责人记录

## 背景

六位成员对应的业务模块已经由小组确认，不再需要开放自主认领。为减少重复认领和口头分工不一致，由组长在创建模块 Epic 时直接设置负责人。

## 决定

- 为用户管理、学生学籍、选课系统、图书馆、商店、医院分别创建一个模块 Epic Issue。
- 组长按照已确认的分工直接设置每个 Epic 的 `Assignee`。
- 六位成员（包括组长）每人主责一个业务模块；六个 Epic 各有且只有一位主 Assignee，人员不重复。
- 组长除主责自己的业务模块外，还承担进度统筹、公共接口协调和合并把关；公共工作后续通过单独 Issue 分配，不改变初始业务模块归属。
- Issue 模板中的 `公共/网络`、`数据库`、`文档/发布` 是后续横向任务分类，不是额外业务模块。
- 模块调整须在相关 Issue 中留下原因和交接记录，再由组长修改 Assignee。
- 姓名、学号和联系方式不写入公开仓库；当前负责人以 GitHub Assignee 为准。

## 公平性原则

- 初始阶段所有人都承担一个完整业务模块，组长不免除业务开发责任。
- 工作量不以模块名称判断，而按已验收场景、缺陷、文档、评审和集成贡献综合衡量。
- 每周检查实际工作量；出现明显失衡时，通过支援、结对或后续公共任务进行调整，并保留 Issue 记录。

## 影响与迁移

- Issue 模板和分工文档由“自主认领”改为“组长统一设置”。
- ADR-0002 保留为历史记录并标记被本 ADR 取代。
- 已确定的具体人员只记录在 GitHub Assignee 和课程线下分工表中，避免公开文档过时或暴露隐私。
