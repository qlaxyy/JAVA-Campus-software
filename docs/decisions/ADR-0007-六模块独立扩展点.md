# ADR-0007：六模块使用固定独立扩展点

- 状态：通过
- 日期：2026-08-25
- 决策范围：六人并行开发、请求分发和主导航

## 背景

公共工程骨架最初只在 `CampusServer` 中硬编码 `COMMON.PING`，主窗口也只有连接按钮。如果六位负责人直接添加业务功能，所有人都需要修改同一个请求分发方法和主窗口，容易产生频繁冲突，也会让模块边界失效。

## 决定

- 服务器使用线程安全 `ActionRouter` 按 action 注册唯一 handler。
- 固定六个 `ServerModule` 入口，每位负责人只在自己的 server 包注册本模块 action。
- 固定六个 `ClientModule` 入口和统一主导航，每位负责人只替换自己的占位页面。
- common、client、server 和数据字典都按相同六模块名称划分所有权；功能设计统一维护在模块 Epic 正文中。
- `MainFrame`、`CampusServer` 和模块目录清单作为共享核心，由组长或公共任务 PR 维护。

## 备选方案

### 所有人共同修改一个 switch 和一个主窗口

代码量少，但并行冲突高且缺少所有权边界，未采用。

### 六个独立 Maven 子工程

隔离更强，但会增加依赖、打包和最终集成复杂度，不适合当前课程规模，未采用。

## 影响与验证

- 新 action 重复注册会在启动阶段失败，避免静默覆盖。
- handler 抛出的运行时异常被转换为公共服务器错误，内部细节不返回客户端。
- 每个模块都已有稳定的 client/server/common/database 修改位置，并以模块 Epic 作为唯一功能设计入口。
- 通过路由单元测试以及现有 PING/PONG 集成测试验证；六个业务 handler 仍由各模块后续实现。
