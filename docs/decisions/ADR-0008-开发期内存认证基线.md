# ADR-0008：采用可替换的开发期内存认证基线

- 状态：通过（临时基线）
- 日期：2026-08-25
- 决策范围：六模块开发依赖、登录与会话

## 背景

所有业务模块最终都依赖统一用户、角色和服务器端会话校验，但 Access/JDBC 尚未完成。如果完全等待用户数据库，其他五个模块无法验证受保护请求；如果每个模块各自模拟登录，又会形成六套不兼容身份状态。

## 决定

- 公共层提供 `USER.LOGIN`、`USER.CURRENT_SESSION`、`USER.LOGOUT`、`LoginRequest`、`SessionInfo` 和三种基础角色。
- 服务器暂时使用一套公开虚构用户和内存会话，成功登录生成 32 字节随机 token。
- 客户端通过共享 `ClientContext` 保存会话并自动携带 token。
- 服务器模块只通过 `ServerContext.sessions()` 查询会话，不依赖用户模块的内存实现或未来 DAO。
- 原始密码不进入 Request；开发期发送确定性 SHA-256 proof，并明确记录其重放风险。

## 备选方案

### 等待 Access 用户表完成后再开发其他模块

安全设计更接近最终方案，但会造成全组串行等待，未采用。

### 每个模块自己模拟用户和角色

短期方便，但最终身份、token 和权限无法集成，未采用。

### 立即实现完整 TLS、密码库和权限系统

质量更高，但在数据库和部署环境未确认时范围过大；作为后续正式认证方案评审，不在本基线一次完成。

## 影响与退出条件

- 其他模块现在可以开发登录后请求和服务器角色检查。
- 公开演示密码只用于本项目假数据，不能作为真实安全凭据。
- 用户模块负责人仍对最终账号、密码哈希、账户状态、权限、会话过期和审计负责。
- Access DAO 与正式认证通过测试并替代 `InMemoryAuthenticationService` 后，本临时基线退出；替换不得迫使其他模块直接依赖用户 DAO。
