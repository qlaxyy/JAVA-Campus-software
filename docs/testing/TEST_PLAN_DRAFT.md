# 虚拟校园系统测试计划（持续草稿）

> 当前尚无业务模块代码；公共三模块骨架已有真实构建和网络测试。业务结果必须来自后续自动测试和真实演示，不能预填“通过”。

## 1. 测试目标

- 验证六个业务模块满足需求基线。
- 验证权限、参数、异常和并发规则由服务器端执行。
- 验证客户端、服务器端和数据库在目标环境可部署运行。
- 为测试分析报告、软件设计说明书、项目总结和答辩保存可追溯证据。

## 2. 测试范围

- 用户、学籍、选课、图书馆、商店、医院六个模块。
- 公共 Message、网络、多线程、数据库访问和异常处理。
- 构建、启动、演示数据初始化、JavaDoc 和最终发布包。

范围外：真实支付、短信/邮件、第三方认证、真实医疗/医保和未纳入需求基线的加分功能。

## 4. 测试层次

- 单元测试：服务层业务规则、校验、状态流转和工具类。
- 数据访问测试：DAO CRUD、约束、事务/临界区和初始化数据。
- 协议测试：action 分发、DTO 序列化、错误码和非法消息。
- 集成测试：客户端请求—Socket—服务层—DAO—数据库完整链路。
- 并发测试：课程容量、图书库存、商品库存和医院号源。
- UI 手工测试：表单、空状态、加载状态、成功/失败提示和权限可见性。
- 部署测试：全新环境构建、启动、连接、退出和恢复。

## 5. 严重程度

| 等级 | 定义 | 处理规则 |
|---|---|---|
| P0 | 无法构建/启动、数据损坏、权限绕过、服务器崩溃 | 停止新功能，立即处理 |
| P1 | 必做或医院核心主流程失败 | 功能冻结前清零 |
| P2 | 有替代路径、局部错误或明显体验问题 | 发布候选前尽量处理 |
| P3 | 美化、提示和非核心改进 | 不影响核心交付时处理 |

## 6. 测试数据

- 使用虚构学生、教师、管理员和医院数据。
- 提供固定演示账号，密码不得与成员真实密码相同。
- 覆盖正常、边界、重复、无权限、停用、满容量/库存/号源等数据。
- 初始化应可重复执行，测试间相互污染时提供清理/重置办法。

## 9. 进入与退出条件

进入集成测试前：模块 Issue 已认领、接口和表已评审、主流程本地可运行、初始化数据可用。

进入发布候选前：六模块核心用例通过、P0/P1 清零、`main` 构建通过、部署说明可复现、追踪表无关键空缺。

## 10. 结果与证据管理

- 自动测试结果随 PR 或 CI 保存。
- 手工测试在 Issue 中记录步骤、环境、结果和截图。
- 缺陷使用独立 Issue，关联失败用例和修复 PR。
- 每周把通过数、失败数、P0/P1 和未测范围同步到进度记录。
- 最终测试分析报告只能汇总真实执行结果。
