## 本轮每个人要完成什么

在自己负责的模块内，自选 **1 条小而完整、可现场演示的端到端功能**：

```text
Swing 页面 → Request/DTO → Socket → Server Handler/Service
→ Response/DTO → Swing 显示结果
```

第一轮不要求一次做完整个模块。优先选择低依赖功能，例如查询学籍、查询课程、检索图书、查询商品或查询医院号源；负责人也可以提出同模块内其他合理功能。

完成标准：

- 属于本人负责模块，3—4 天内可以完成；
- 包含可操作页面、服务器处理和返回结果；
- 使用明确的 Action 和可序列化 DTO；
- 服务器端完成参数及必要的登录/权限校验；
- 至少有 1 个自动测试；
- 更新本模块设计与数据字典；
- `mvn clean verify` 成功，PR 附测试说明和界面截图。

## 开始开发

```powershell
git switch main
git pull --ff-only origin main
mvn clean verify
git switch -c feat/<module>-<issue>-<summary>
```

## 每个人的模块 Epic 怎么用

**Issue 正文由组长维护，成员不要修改。评论区只在下面 3 个时间点留言，不写每日流水账：**

### 1. 开工前：写一次本轮计划

```text
【本轮计划】
功能：一句话说明这轮做什么
页面：页面名称和主要操作
Action：MODULE.VERB
验收：一个正常场景 + 一个异常/权限场景
公共影响：无 / 需要修改什么共享内容
```

留言后直接创建功能分支，无需等待组长确认。完整 DTO 字段、业务流程写进本模块设计文档；表和字段写进本模块数据字典，不复制到 Issue。

### 2. 开发中：只有阻塞或方案明显变化时留言

```text
【阻塞/变更】当前情况 / 原因 / 需要谁协助
```

### 3. 创建 PR 后：留下结果

```text
【已提交】PR 链接 / 已完成功能 / 未完成或后续事项
```

只影响本人模块的想法直接更新模块文档；需要修改共享核心或影响其他模块时，另建一个 `[公共]` Issue 讨论后再改。

## 调出客户端页面

推荐在 IDEA 中先运行 `ServerMain` 左侧的绿色三角，再运行 `ClientMain` 左侧的绿色三角。服务器保持运行后，客户端 Swing 页面会自动弹出。

需要使用命令行时，先执行 `mvn clean package`，再打开两个 PowerShell：

```powershell
# 第一个终端：服务器
java -cp "vcampus-common\target\classes;vcampus-server\target\classes" edu.seu.vcampus.server.ServerMain

# 第二个终端：客户端
java -cp "vcampus-common\target\classes;vcampus-client\target\classes" edu.seu.vcampus.client.ClientMain
```

完整运行说明见 [公共工程骨架与运行](11-公共工程骨架与运行.md)。

## 只需遵守 5 条规则

1. 不直接在 `main` 开发；一个具体功能使用一个分支和一个 PR。
2. 原则上只修改自己模块的 common、client、server、设计和数据字典目录。
3. 客户端不直连数据库；使用现有 Socket、Request/Response 和登录 Token。
4. 权限由服务器端校验，Swing 网络请求不得阻塞界面线程。
5. 要改公共接口、公共页面或其他模块时，先在 Issue 说明并联系组长。

## 完成后

先提交自己的修改，再同步最新版 `main`：

```powershell
git fetch origin
git merge origin/main
mvn clean verify
git push -u origin <自己的分支名>
```

随后在 GitHub 创建 `自己的分支 → main` 的 Pull Request，写 `Part of #Epic编号` 并邀请至少一位非作者检查。模块 Epic 在整个模块完成前保持 Open，不要因为第一条功能使用 `Closes` 提前关闭。已有 PR 后继续 `git push`，PR 会自动更新。

公共接口冲突、数据库方案冲突或最新版 `main` 无法构建时，不要各自另写一套实现，按上面的“阻塞/变更”格式留言并通知相关成员。
